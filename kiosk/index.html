Sent is the literal HTTP request this page made — method, path and JSON body. Received is the status, the round trip in milliseconds, and the full response body, scrollable when it is long.

Neither is gRPC. Envoy turns each call into a gRPC request against legacy.inventory.v1.Inventory and turns the protobuf reply back into the JSON you see. The service has no HTTP server, so nothing in either box could have reached it directly.

servedBy in the response names the backend pod that answered. The inventory Service is headless, so Envoy holds a connection to each of the three replicas and picks one per request — refresh a few times and the name changes. State lives in MongoDB, which is why any replica can answer and why an item added here survives a restart.
